Beluga AI v2.13.1 ships two sprints of CLI work: a development loop with mock LLM support and a first-class evaluation framework.

The development loop (v2.12.0) adds `beluga run`, `beluga dev`, and `beluga test`. The development mode variant starts a mock LLM by default, hot-reloads on source changes, and wires an OpenTelemetry trace exporter automatically when OTEL_EXPORTER_OTLP_ENDPOINT is set. Agents that previously required a real API call on every iteration can now iterate locally without touching the network.

The mock LLM registers under the same interface as every real Beluga provider. A test file that imports `github.com/lookatitude/beluga-ai/v2/llm/providers/mock` and calls `llm.New("mock", ...)` gets a deterministic, in-process model. Swap the provider name for a real one and the same test runs against the API — no structural changes.

The evaluation CLI (v2.13.0) adds `beluga eval`, which runs structured evaluation cases against a running agent and reports pass/fail with structured output. `beluga new eval` scaffolds the harness. `beluga test ./...` picks up eval cases automatically, so evaluation fits into the existing test loop.

v2.13.1 adds documentation for the framework conventions that tie the eval CLI, the test runner, and the observability pipeline together.

No breaking changes. Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.1

Full release notes: https://beluga-ai.org/blog/v2.13.1-release/
