1/6
Beluga AI v2.13.2 is out. The headline: `beluga eval`, a CLI for running structured evaluation suites against your agents. It closes out the DX-1 initiative — an end-to-end authoring and evaluation loop in a single binary.

2/6
The dev loop from v2.12.0 is the other half: `beluga run` against a live provider, `beluga dev` against a deterministic mock LLM, and `beluga test` for Go unit tests against the mock. Same observability bootstrap across all three, so traces compare apples-to-apples.

3/6
`beluga eval` is deliberately separate from `beluga test`. Unit tests verify your Go code does what you wrote. Evals verify your agent produces the outputs you care about on a fixed set of inputs.

4/6
Scaffold with `beluga new eval <name>`. You get a directory of YAML case files plus a `judge.go` stub. Cases declare input, expected-output contract (exact, fuzzy, or custom predicate), and any per-case model overrides.

5/6
CI integration is one flag: `beluga eval run ./evals --format=json` emits structured output and exits non-zero on failure. Wire it into a workflow step and regressions block the merge.

6/6
No breaking changes across v2.12.0, v2.13.0, v2.13.1, or v2.13.2. Upgrade with: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
