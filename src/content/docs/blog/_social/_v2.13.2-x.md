1/7
Beluga AI v2.13.2 is out. The headline: `beluga eval` — a new CLI command that turns a scaffolded Beluga project into a self-contained evaluation harness. One command, one dataset, one report.

2/7
`beluga eval <dataset>` runs your project once per dataset row over exec-once IPC. It sets `BELUGA_ENV=eval` and `BELUGA_EVAL_SAMPLE_JSON` per row, reads structured IPC output back, and scores results. No bespoke runner code.

3/7
The default metric is `ExactMatch` — case-insensitive, whitespace-trimmed, zero credentials needed to get a first signal. Output ships in three formats: a text summary for the terminal, `eval-report.json` for tooling, and JUnit XML (`--format junit`) for PR annotations.

4/7
OTel is wired in: `gen_ai.evaluation.*` spans, a `beluga.eval.metric.score` histogram, and a `beluga.eval.run_id` you can join across signals. Eval runs show up in the same dashboards as production traffic.

5/7
New scaffolds get `.beluga/eval.yaml`, a `.beluga/eval.smoke.json` (3-row mock so CI runs without provider credentials), and a `make eval-ci` target. Projects scaffolded with `beluga init` can run `make eval-ci` on the first commit.

6/7
Also covered in this announcement window: v2.12.0 shipped the dev-loop trio — `beluga run`, `beluga dev`, `beluga test` — alongside real OTel bootstrap. The CLI is now usable end-to-end: scaffold, run, dev, test, evaluate.

7/7
No breaking changes. Update with: go get github.com/lookatitude/beluga-ai/v2@v2.13.2

Full release notes: https://beluga-ai.org/blog/v2.13.2-release/
