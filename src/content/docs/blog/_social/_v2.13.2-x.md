1/7
Beluga AI v2.13.2 is out. The headline across the v2.12.0–v2.13.2 window: a working dev loop. `beluga run`, `beluga dev`, `beluga test`, and `beluga eval` — the four commands that make iterating on an agent feel like iterating on any other Go service.

2/7
`beluga run` builds and execs your scaffolded project with signal forwarding wired in. `beluga dev` adds a file-watch rebuild/restart loop and a loopback playground UI that surfaces OTel spans, stderr, and cost panels while you work.

3/7
`beluga test` pins the test environment so suites run offline with no API key: `BELUGA_LLM_PROVIDER=mock` and `OTEL_SDK_DISABLED=true`. Pair it with the new `llm/providers/mock` — a FIFO fixture-queue LLM for deterministic test scenarios.

4/7
`o11y.BootstrapFromEnv` now ships real OTLP/HTTP and stdout exporters with a no-op fallback when nothing is configured. The cross-OS integration matrix covers Ubuntu, macOS, and Windows.

5/7
v2.13.0 added `beluga eval`: run the eval/judge pipeline from the CLI. It scaffolds an eval branch with test datasets and judge config so evaluation isn't a separate project to set up.

6/7
This is sprint 4 of the DX-1 developer experience initiative. The arc so far: CLI foundation (v2.10.0) → scaffolding (v2.11.0) → dev loop (v2.12.0) → eval CLI (v2.13.0). v2.11.1, v2.13.1, and v2.13.2 were maintenance: docs, deps, CI.

7/7
No breaking changes. Update with: go get github.com/lookatitude/beluga-ai/v2@v2.13.2

Full release notes: https://beluga-ai.org/blog/v2.13.2-release/
