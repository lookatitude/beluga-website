1/6
Beluga AI v2.13.0 shipped the `beluga eval` CLI — the eighth subcommand in the Beluga toolchain. Run your agent against a dataset, compute metrics, and emit a report. No bespoke evaluation harness required.

2/6
The architecture worth knowing: exec-once IPC. The evaluator spawns your agent binary once per sample row as a subprocess. The child reads `BELUGA_EVAL_SAMPLE_JSON`, emits a protocol probe (`{"beluga_eval_protocol":1}`), runs your agent logic, and returns a populated result. No long-lived harness state to reason about.

3/6
Built-in metrics in v2.13.0: `exact_match` (case-insensitive, whitespace-trimmed) and `latency` (wall-clock ms). Planned: LLM judges, Braintrust, DeepEval, RAGAS.

4/6
OTel instrumented end to end. `eval.run` root span, `eval.row` per-sample spans, `gen_ai.evaluation.result` events per metric score, and a `beluga.eval.metric.score` histogram keyed on metric + dataset so cardinality stays bounded. Eval runs show up in the dashboards you already run.

5/6
Report formats: tabular text to stdout, `eval-report.json` unconditionally, and `--format junit` for `dorny/test-reporter` PR annotations. `beluga init` and `beluga new` scaffold an eval branch into generated projects, a `.beluga/eval.yaml` config, a deterministic 3-row smoke dataset, and a `make eval-ci` target.

6/6
v2.13.1 added DX-1 S4 workflow docs; v2.13.2 is CI housekeeping, no API changes. Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
