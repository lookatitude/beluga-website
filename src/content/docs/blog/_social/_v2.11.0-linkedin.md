Beluga AI v2.11.0 ships today with two CLI scaffolding commands: `beluga init` and `beluga new`.

Before this release, starting a new Beluga project required assembling the same set of pieces by hand: Go module setup, provider configuration, observability bootstrapping, and a CLI entry point. Developers experienced with the framework knew the pattern, but it was never encoded anywhere a new user could run. That friction slowed down first evaluations and early project starts.

`beluga init` creates a new Beluga project from the command line with the correct structure in place. `beluga new` scaffolds individual components — agents, tools, and similar building blocks — into an existing project, generating the boilerplate code that would otherwise be written by hand every time.

Both commands build on the Cobra CLI foundation introduced in v2.10.0, which also added `beluga provider` and `beluga version` subcommands and observability bootstrapping. This release makes that foundation practical for day-one use.

This announcement also covers v2.10.1 (module path correction to `github.com/lookatitude/beluga-ai/v2`) and v2.10.2 (security hardening, UsageCount mutation removal).

Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.11.0
