Beluga AI v2.13.2 ships today and closes out the DX-1 initiative. The headline is `beluga eval`, a CLI for running structured evaluation suites against Go agents, alongside the `beluga run`, `beluga dev`, and `beluga test` commands introduced in v2.12.0.

Iterating on agents used to mean stitching together three different harnesses: one for running against a real provider, one for a fast local mock, and another for regression checks on fixed inputs. v2.12.0 put all three modes on a consistent CLI surface — `beluga run` hits the configured live provider, `beluga dev` runs the same agent graph against a deterministic mock LLM, and `beluga test` runs Go unit tests against that mock. Each mode emits the same structured traces, so a local run and a production run produce comparable telemetry.

v2.13.0 added `beluga eval`. Scaffold a suite with `beluga new eval <name>`, express each case as YAML with an expected-output contract, and run the whole suite or a single case from the CLI. The `--format=json` mode is designed for CI: structured output, non-zero exit on failure, one step in a workflow to block regressions.

This announcement also covers v2.13.1 and v2.13.2 (documentation and audit passes, no user-visible changes).

No breaking changes. Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
