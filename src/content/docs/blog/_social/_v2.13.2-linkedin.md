Beluga AI v2.13.2 is out, closing a developer-experience sprint focused on the inner loop of building agents in Go.

The problem: evaluating LLM-driven code is awkward. Most teams end up with a separate harness, a YAML config, and a runner that doesn't share tooling with the rest of the codebase. Eval results live somewhere other than test results, and CI integration becomes a project of its own.

The solution in v2.13.0 is `beluga eval`. Scaffold an eval branch from the CLI, write cases as table-driven Go tests, and run them through Go's standard testing package. The same `go test` command runs your unit tests and your evals, with the same reporting, the same flags, and the same CI pipeline.

The earlier v2.12.0 release in the same sprint added `beluga run`, `beluga dev` with hot reload, and `beluga test` with a built-in mock LLM and observability bootstrap. Together that gives you a tight local loop and deterministic CI without API keys or token spend.

v2.13.1 and v2.13.2 are documentation and CI maintenance. No breaking changes across the line.
