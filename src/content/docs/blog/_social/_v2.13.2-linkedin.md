Beluga AI v2.13.2 closes the inner developer loop for Go-native agents.

Three new CLI subcommands — `beluga run`, `beluga dev`, and `beluga test` — collapse the build, run, and test cycle into commands that mirror what Go developers already expect from `go run` and `go test`. `beluga dev` runs with verbose logs, a local observability sink, and the mock LLM available as a fallback when no API key is set, so traces and metrics show up from the first invocation.

The new mock LLM provider lets unit tests exercise agent logic — multi-turn reasoning, tool calls, guard policies — without making real API calls or maintaining per-test stub scaffolds. It registers through the same provider pattern as every real backend.

`beluga eval` runs evaluation suites against an agent and reports pass/fail per case. The first run scaffolds an `eval/` directory with suite definitions, fixtures, and judge configuration; subsequent runs execute the suite. Evaluation moves into the inner loop, where prompt and tool changes can be scored in the same shell session without leaving the CLI.

This release covers the window from v2.11.1 through v2.13.2. No breaking changes.
