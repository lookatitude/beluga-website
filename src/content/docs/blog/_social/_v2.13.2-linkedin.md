Beluga AI v2.13.0 shipped the `beluga eval` CLI, the eighth subcommand in the Beluga toolchain.

Evaluating AI agents in CI usually means assembling a bespoke harness: a runner that feeds sample inputs to the agent, a scoring layer, a reporter, and a way to surface results on pull requests. Every team writes a version of the same thing, and the results rarely flow into the observability stack the rest of the system uses.

`beluga eval` covers that surface. Point it at a dataset JSON file, pass one or more `--metric` flags, and it runs your agent against each sample and writes a report. The evaluator uses an exec-once IPC model: it spawns your agent binary once per row as a subprocess, passes the sample through `BELUGA_EVAL_SAMPLE_JSON`, and reads the result back. Built-in metrics in v2.13.0 are `exact_match` and `latency`, with LLM judges and third-party integrations (Braintrust, DeepEval, RAGAS) on the roadmap.

One concrete detail worth calling out: eval runs are OTel-instrumented. The `eval.run` and `eval.row` spans, `gen_ai.evaluation.result` events, and `beluga.eval.metric.score` histogram flow into whatever tracing backend you already use. For CI, `--format junit` produces output compatible with `dorny/test-reporter` for PR annotations.

v2.13.1 added framework-workflow docs; v2.13.2 is CI housekeeping.
