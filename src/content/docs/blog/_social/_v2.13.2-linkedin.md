Beluga AI v2.13.2 ships today with `beluga eval`, a new CLI command that turns a scaffolded Beluga project into a self-contained evaluation harness.

`beluga eval <dataset>` runs your project once per dataset row using exec-once IPC. It sets `BELUGA_ENV=eval` and `BELUGA_EVAL_SAMPLE_JSON` for each sample, reads structured output back, and scores it. The default metric is `ExactMatch` (case-insensitive, whitespace-trimmed), which means a new project can produce a first evaluation signal without any provider credentials configured.

Results emit in three formats: a text summary for local runs, `eval-report.json` for downstream tooling, and JUnit XML for PR annotations via `--format junit`. OpenTelemetry is wired in by default — `gen_ai.evaluation.*` spans, a `beluga.eval.metric.score` histogram, and a `beluga.eval.run_id` for cross-signal joins — so evaluation runs land in the same dashboards as production traffic.

New projects scaffolded with `beluga init` now ship `.beluga/eval.yaml`, a 3-row `.beluga/eval.smoke.json` mock, and a `make eval-ci` target that runs in CI without external dependencies.

This announcement also covers v2.12.0, which shipped the dev-loop commands `beluga run`, `beluga dev`, and `beluga test`, plus real OTel bootstrap.
