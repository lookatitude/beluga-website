Beluga AI v2.13.2 ships today. The headline feature, delivered in v2.13.0: `beluga eval` — a CLI command that runs structured evaluations against agents without requiring a custom test harness.

This release completes a three-step developer experience arc. v2.11.0 added scaffolding (`beluga init`, `beluga new`) so projects and components start from a known-good template. v2.12.0 added the local development loop: `beluga run` executes agents with real observability, `beluga dev` supports iteration with a mock LLM to avoid burning tokens, and `beluga test` wires the framework into the Go test runner. v2.13.0 closed the loop with `beluga eval` and a scaffolded evaluation package, so teams can define a suite, run it against an agent, and track behavior across versions.

The practical effect: scaffold, develop, and evaluate are all first-class CLI operations. What used to be a collection of internal scripts at every team adopting the framework is now standard surface area.

v2.13.1 and v2.13.2 were documentation and CI maintenance. No API changes and no breaking changes across this announcement window.

Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
