Beluga AI v2.13.2 ships today with `beluga eval`: a CLI command for running LLM-as-Judge evaluations directly from the terminal.

The eval/judge package — LLM-as-Judge with structured rubrics — has been part of Beluga since v2.8.0. Until now, using it required writing a Go harness for each project: loading rubrics, wiring the judge, collecting results, formatting output. Teams that wanted disciplined evaluation paid a setup cost every time. v2.13.0 removes that cost.

`beluga eval init` scaffolds a structured eval branch with rubrics, fixtures, and config laid out in the expected shape. `beluga eval` runs the suite and reports scores. Evaluation moves from a side project into the inner development loop.

Combined with v2.12.0's `beluga run`, `beluga dev`, and `beluga test` commands — which bootstrap a mock LLM and observability by default — the loop now closes end to end: code, run, test, evaluate. All four steps from one CLI, no boilerplate per project.

Both releases are part of the DX-1 sprint focused on bringing the day-to-day developer experience up to the level of the framework's runtime. No breaking changes through v2.13.2.

Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
