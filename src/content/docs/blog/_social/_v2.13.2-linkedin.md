Beluga AI v2.13.2 closes out the DX-1 series with `beluga eval` — a CLI command for running LLM-as-Judge evaluations against agent outputs.

Two things make it CI-friendly out of the box:

- Every run writes `eval-report.json` at the project root, so artifact pipelines know exactly where to look.
- `--format junit` emits JUnit XML, which works directly with GitHub Actions test reporters (dorny/test-reporter and compatible actions). Your eval suite shows up alongside unit tests in PR checks.

It wires into the `eval/judge` package for rubric-driven scoring, runs a per-row 30-second timeout, and scaffolds an eval branch in your project binary so the CLI knows how to execute it.

This is the fourth and final stop on the DX-1 roadmap. v2.12.0 shipped the dev loop (`beluga run` / `dev` / `test`), a mock LLM provider for offline iteration, and a real OTel bootstrap for local observability. v2.11.0 added scaffolding (`beluga init` / `beluga new`).

Upgrade with `go get github.com/lookatitude/beluga-ai/v2@v2.13.2`.

Full release notes: https://beluga-ai.org/blog/v2.13.2-release/
