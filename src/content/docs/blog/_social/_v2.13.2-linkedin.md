Beluga AI v2.12.0 and v2.13.0 complete the CLI developer loop for building Go AI agents.

Before these releases, running an agent during development meant either making live API calls on every iteration or maintaining project-specific mock harnesses. Neither approach transferred between teams or produced consistent CI results.

v2.12.0 ships `beluga run`, `beluga dev`, and `beluga test`. `beluga dev` runs your agent against a deterministic mock LLM — no external calls, no cost, reproducible output. `beluga test` uses the same mock for CI. Real OTLP trace export is wired in from the start: set `BELUGA_OTEL_ENDPOINT` and all three commands emit traces in the same shape as production.

v2.13.0 adds `beluga eval`. It reads an evaluation dataset, runs it through configured metrics, and reports scores to stdout in a format you can diff across runs. It's backed by the same `eval` package available in Go code, so there's no behavioral gap between programmatic and CLI evaluation.

These releases complete the four-sprint DX-1 initiative: `beluga init` for project scaffolding, `beluga new` for component scaffolding, `beluga run/dev/test` for the dev loop, and `beluga eval` for evaluation.

Upgrade: go get github.com/lookatitude/beluga-ai/v2@v2.13.2
