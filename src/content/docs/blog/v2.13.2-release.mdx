Beluga AI v2.13.0 ships `beluga eval`, a CLI command that turns any scaffolded Beluga project into a self-contained evaluation harness. The v2.13.2 patch tag closes out the release window with CI and changelog housekeeping; the headline work landed in v2.13.0 on April 22, 2026, as part of DX-1 Sprint 4 (LOO-154).

## Why it matters

Agent evaluation is usually a separate stack: a different runtime, a different config file, a different set of credentials, often a hosted SaaS. That distance is where regressions hide. `beluga eval` collapses the gap by running the same scaffolded project the developer already runs locally, once per dataset row, with two environment variables flipped. The agent under test is the agent in production. The harness is a thin shell around it.

The default metric needs no API keys, the smoke fixture is three rows long, and the whole CI integration runs under 90 seconds on a cold cache. Teams can adopt it the same day they upgrade.

## What shipped

The new command is `beluga eval <dataset>`. It executes the scaffolded project once per dataset row through an exec-once IPC contract, sets `BELUGA_ENV=eval` and `BELUGA_EVAL_SAMPLE_JSON` for each invocation, collects the trajectories, scores them with one or more configured metrics, and emits an `eval-report.json`.

Flags cover the operational surface developers actually need:

- `--config` and `--dataset` point at the eval configuration and the rows to score.
- `--metric` is repeatable, so a single run can compute multiple scores.
- `--format` selects `text`, `json`, or `junit` output; the JUnit XML form annotates pull requests through tools like dorny/test-reporter.
- `--row-timeout`, `--max-rows`, and `--parallel` shape the run.
- `--dry-run` validates the configuration without invoking the agent.

The default metric is `ExactMatch`: case-insensitive, whitespace-trimmed comparison between expected and actual output. It requires zero credentials, which keeps the smoke path green on every machine.

OpenTelemetry GenAI spans emit `gen_ai.evaluation.*` signals during the run. The histogram `beluga.eval.metric.score` is keyed by metric name and dataset, never by row ID, which keeps cardinality bounded for production observability backends. A `beluga.eval.run_id` resource attribute joins metrics, traces, and the JSON report across signals.

### Scaffold changes in generated projects

New projects scaffolded with this release pick up four artifacts:

- `.beluga/eval.yaml` holds the eval configuration.
- `.beluga/eval.smoke.json` ships a three-row mock fixture so the harness has something to score on day one.
- A `make eval-ci` target pins five canonical environment variables for CI parity.
- The scaffolded `main.go` now branches on `BELUGA_ENV=eval`, reads `BELUGA_EVAL_SAMPLE_JSON`, emits the IPC probe, runs the agent, and returns the populated sample.

The IPC contract is a two-line protocol. The first line is the probe `{"beluga_eval_protocol":1}`, which signals readiness within five seconds. The second line is the populated `EvalSample` JSON. Anything else on stdout is treated as application logging.

### The eval branch in main.go

The same binary handles both the production run and the eval invocation; the only switch is `BELUGA_ENV`.

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"os"

	"github.com/lookatitude/beluga-ai/v2/config"
	"github.com/lookatitude/beluga-ai/v2/llm"
	_ "github.com/lookatitude/beluga-ai/v2/llm/providers/anthropic"
)

type EvalSample struct {
	Input          string  `json:"input"`
	ExpectedOutput string  `json:"expected_output"`
	ActualOutput   string  `json:"actual_output"`
	ExactMatch     float64 `json:"exact_match"`
}

func main() {
	ctx := context.Background()

	if os.Getenv("BELUGA_ENV") == "eval" {
		// IPC probe: signal readiness to the eval harness
		fmt.Println(`{"beluga_eval_protocol":1}`)

		raw := os.Getenv("BELUGA_EVAL_SAMPLE_JSON")
		var sample EvalSample
		if err := json.Unmarshal([]byte(raw), &sample); err != nil {
			fmt.Fprintln(os.Stderr, "eval: unmarshal sample:", err)
			os.Exit(1)
		}

		model, err := llm.New("anthropic", config.ProviderConfig{
			APIKey: os.Getenv("ANTHROPIC_API_KEY"),
			Model:  "claude-haiku-4-5-20251001",
		})
		if err != nil {
			fmt.Fprintln(os.Stderr, err)
			os.Exit(1)
		}

		resp, err := model.Generate(ctx, sample.Input)
		if err != nil {
			fmt.Fprintln(os.Stderr, err)
			os.Exit(1)
		}
		sample.ActualOutput = resp.Content

		out, err := json.Marshal(sample)
		if err != nil {
			fmt.Fprintln(os.Stderr, err)
			os.Exit(1)
		}
		fmt.Println(string(out))
		return
	}

	// Normal run path
	model, err := llm.New("anthropic", config.ProviderConfig{
		APIKey: os.Getenv("ANTHROPIC_API_KEY"),
		Model:  "claude-haiku-4-5-20251001",
	})
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	resp, err := model.Generate(ctx, "What is a language model?")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	fmt.Println(resp.Content)
}
```

The mock provider helper `FixturesFromTurns(Turn)` enables deterministic replay without API credentials, which is what keeps the smoke fixture credential-free.

### CI integration

A new `eval-integration.yml` job scaffolds a fresh project, runs `make eval-ci`, and asserts three things: three samples were scored, zero rows errored, and `exact_match ≥ 0.999`. The budget is under 90 seconds on a cold cache. Teams that adopt this layout get the same guarantees on their own pipelines.

## What's next

Real-provider metrics and integrations with Braintrust, DeepEval, and RAGAS are deferred to Sprint 4.5. The current release intentionally keeps the metric surface small: `ExactMatch` is enough to ship a green CI signal, and the OTel histogram already gives operators the cardinality-safe shape they need to wire dashboards against richer metrics later.
